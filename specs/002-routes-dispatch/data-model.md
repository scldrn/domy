# Data Model: Routes and Dispatch

Phase 1 of [plan.md](plan.md). Extends
[feature 001's data model](../001-shipment-registration/data-model.md) and follows its
conventions (snake_case plural tables, UUID keys with client-generated identifiers for
creations, integer COP, `timestamptz` in UTC, `date` in `America/Bogota`, append-only
events).

## Enumerations

| Enum | Values | UI labels |
| --- | --- | --- |
| `route_status` | `draft`, `in_progress`, `finished`, `cancelled` | En preparación, En curso, Finalizada, Cancelada |
| `stop_kind` | `pickup`, `delivery`, `errand` | Recogida, Entrega, Diligencia |
| `task_status` | `pending`, `completed`, `failed` | Pendiente, Completada, Novedad |
| `handover_status` | `pending`, `confirmed`, `cancelled` | Traspaso pendiente, Traspaso confirmado, Traspaso cancelado |
| `route_event_type` | `created`, `shipment_added`, `shipment_removed`, `reordered`, `courier_set`, `dispatched`, `dispatch_undone`, `reassigned`, `handover_requested`, `handover_confirmed`, `handover_cancelled`, `cancelled`, `finished` | — |

Added to feature 001's `shipment_event_type`: `reassigned`, `handover_confirmed`,
`handover_cancelled`.

## Tables

**`routes`**

| Column | Type | Rules |
| --- | --- | --- |
| `id` | uuid | Generated by the client (FR-020) |
| `service_date` | date | Not null |
| `number` | integer | Unique with `service_date`; assigned at creation; kept when cancelled (FR-002) |
| `courier_id` | uuid → couriers | Optional while `draft`; required from `in_progress` on |
| `status` | `route_status` | Not null; default `draft` |
| `cancel_reason` | text | Required when `cancelled`; 5–200 characters |
| `dispatched_at`, `dispatched_by` | timestamptz, uuid → users | Set at dispatch; cleared when the dispatch is undone |
| `finished_at` | timestamptz | Set when the route becomes `finished` |
| `version` | integer | Optimistic concurrency (FR-021) |
| `created_by` | uuid → users | Not null |

- Partial unique index on `(courier_id) WHERE status = 'in_progress'`: one route in progress
  per courier, across service dates (FR-009).
- Check: `status in ('in_progress', 'finished') ⇒ courier_id is not null`;
  `status = 'cancelled' ⇔ cancel_reason is not null`.
- Routes are never deleted (FR-017).

**`route_stops`**

| Column | Type | Rules |
| --- | --- | --- |
| `route_id` | uuid → routes | Not null |
| `position` | integer | Unique with `route_id` (deferrable, so a reorder swaps positions in one transaction) |
| `kind` | `stop_kind` | Not null |
| `address` | text | Snapshot of the place: pickup address, recipient address, handoff place, or errand location |
| `neighborhood_id` | uuid → neighborhoods | Optional (errands may have none) |

A pickup stop is identified within a route by its normalized `address` and
`neighborhood_id`: shipments sharing both share the stop (FR-005).

**`route_tasks`**

| Column | Type | Rules |
| --- | --- | --- |
| `stop_id` | uuid → route_stops | Not null |
| `shipment_id` | uuid → shipments | Not null |
| `kind` | `stop_kind` | Same as the stop's kind |
| `status` | `task_status` | Default `pending`; changed by feature 003 |
| `completed_at` | timestamptz | Set with `completed` or `failed` |
| `completed_by_courier_id` | uuid → couriers | Courier who did it; kept when the route is reassigned (FR-015) |
| `blocked_by_handover_id` | uuid → handovers | Set while a handover is pending: the task cannot be completed (FR-025) |

- Partial unique index on `(shipment_id, kind) WHERE status = 'pending'`, so a shipment has
  at most one pending pickup task and one pending delivery task at a time.
- Check: `blocked_by_handover_id is null or status = 'pending'`, so a task blocked by a
  pending handover cannot be completed (FR-025).
- A pickup stop has one or more tasks; a delivery or errand stop has exactly one.
- Pending tasks and stops left empty are removed when a shipment leaves the route;
  `completed` and `failed` tasks are never removed (research R10).

**Added to `shipments`** (feature 001)

| Column | Type | Rules |
| --- | --- | --- |
| `route_id` | uuid → routes | Route currently carrying the shipment; null while `registered` (FR-004) |
| `custody_courier_id` | uuid → couriers | Courier who holds the package: set at pickup (feature 003), changed only by a confirmed handover (FR-025) |

Check: `status = 'registered' ⇒ route_id is null`; `status in ('assigned', 'dispatched') ⇒
route_id is not null`.

**`handovers`**

| Column | Type | Rules |
| --- | --- | --- |
| `id` | uuid | Generated by the server; the request that creates it is exactly-once by its `actionId` |
| `shipment_id` | uuid → shipments | Not null; must be `picked_up` when requested |
| `from_courier_id`, `to_courier_id` | uuid → couriers | Not null; different (moving a picked-up shipment between routes of the same courier creates no handover) |
| `from_route_id`, `to_route_id` | uuid → routes | Not null; equal when a whole route is reassigned |
| `reason` | text | 5–200 characters |
| `status` | `handover_status` | Default `pending` |
| `requested_by`, `requested_at` | uuid → users, timestamptz | Not null |
| `resolved_by`, `resolved_at` | uuid → users, timestamptz | Set on confirmation or cancellation |
| `resolved_on_behalf` | boolean | True when the dispatcher confirmed for the courier ("registrado por despacho") |

Partial unique index on `(shipment_id) WHERE status = 'pending'`. Moving the shipment again
while a handover is pending cancels it and creates a new one from the courier in
`custody_courier_id` (FR-025).

**`route_events`** (append-only, FR-022)

| Column | Type | Rules |
| --- | --- | --- |
| `route_id` | uuid → routes | Not null |
| `type` | `route_event_type` | Not null |
| `actor_user_id` | uuid → users | Not null |
| `occurred_at`, `recorded_at` | timestamptz | Not null |
| `shipment_id` | uuid → shipments | Set for shipment-level events |
| `from_courier_id`, `to_courier_id` | uuid → couriers | Set for `courier_set`, `reassigned`, and handover events |
| `reason` | text | Reassign, undo dispatch, cancel |
| `changes` | jsonb | Before and after (stop order, shipments, status) |
| `client_event_id` | uuid | Unique, optional; the request's `actionId`, set on the first event an action writes; further events of the same action leave it null (research R4) |

**Added to `shipment_events`** (feature 001): `route_id` uuid → routes, set on every status
change caused by a route and on reassignment and handover events (FR-022, SC-005).

## Shipment lifecycle: transitions owned by this feature

These rows replace the rows marked "002" in feature 001's lifecycle table. The table lives
once in `packages/domain/src/shipment-lifecycle.ts`.

| From | To | Trigger |
| --- | --- | --- |
| `registered` | `assigned` | Added to a route in `draft` |
| `registered` | `dispatched` | Added to a route `in_progress` |
| `assigned` | `registered` | Removed from a route, or route cancelled |
| `assigned` | `dispatched` | Route dispatched |
| `dispatched` | `registered` | Removed before pickup |
| `dispatched` | `assigned` | Dispatch undone |
| `assigned`, `dispatched` | `voided` | Voided (feature 001); leaves the route in the same transaction (FR-013) |

Moving a shipment to another route (FR-014): a shipment not picked up takes the status that
matches the target route (`assigned` in a `draft` route, `dispatched` in one `in_progress`);
a `picked_up` shipment stays `picked_up` and can only move to a route `in_progress`.

A `finished` or `cancelled` route never reopens (FR-012).

[Feature 003](../003-courier-app/data-model.md) extends this model: `stop_kind` gains
`return`, `route_tasks` gains `problem_note`, `shipments` gains `held_at_office`,
`return_decided`, and `needs_review`, and the unassigned list also includes held shipments
that are on no route.

## Route lifecycle

| From | To | Trigger | Rules |
| --- | --- | --- | --- |
| — | `draft` | Create | Service date today or later; at least one shipment; confirmation beyond 15 shipments |
| `draft` | `in_progress` | Dispatch | Courier set, at least one shipment, courier without a route in progress |
| `in_progress` | `draft` | Undo dispatch | No task `completed` or `failed`, and no shipment `picked_up` on the route (including one received through a handover); reason required (FR-026) |
| `draft` | `cancelled` | Cancel | Reason required; shipments return to `registered` |
| `in_progress` | `finished` | Automatic | No `pending` task and no `pending` handover (FR-012) |

`finished` and `cancelled` are final.

## Derived values

- **Progress**: stops with no pending task ÷ total stops.
- **COD to collect**: sum of `cod_amount` of the shipments currently on the route; it does
  not change with progress (FR-018).
- **Flags**: feature 001's flag rule applied to the route's shipments.
- **Unassigned**: shipments `registered` with `service_date ≤` the selected date.
- **Routes from previous days**: `status = 'in_progress'` and `service_date <` today.
- **Custody history** (SC-005): the shipment's events of type `status_changed` to
  `picked_up`, `reassigned`, and `handover_confirmed`, in order.
