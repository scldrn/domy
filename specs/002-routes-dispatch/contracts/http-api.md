# HTTP API Contract: Routes and Dispatch

Extends [feature 001's contract](../../001-shipment-registration/contracts/http-api.md) and
follows its conventions: JSON under `/api`, Zod schemas from `packages/domain`, session
cookie, integer COP, Spanish error messages, no `DELETE` endpoints, path parameters are
record `id`s.

## Conventions added by this feature

- **Exactly-once actions** (FR-020): every mutating request body includes `actionId`, a UUID
  generated by the client. A repeated `actionId` returns `200` with the current route and
  has no further effect. Route creation also includes the route `id`.
- **Concurrency** (FR-021): every mutating request on an existing route includes its
  `version`; a stale one returns `409 version_conflict`.
- **Roles**: every endpoint below is for the owner and the dispatcher only (FR-023).

| Status | `code` | When |
| --- | --- | --- |
| 409 | `shipment_not_registered` | Adding a shipment that is not "Registrado" or is already on a route (FR-003, FR-004) |
| 409 | `courier_busy` | The courier already has a route in progress; includes `routeNumber` (FR-009) |
| 409 | `invalid_stop_order` | A delivery stop before its pickup stop, or a completed stop moved (FR-006) |
| 409 | `shipment_picked_up` | Removing a shipment already picked up (FR-012) |
| 409 | `route_has_completed_stops` | Undoing a dispatch after a stop was completed or while the route holds a picked-up shipment (FR-026) |
| 409 | `route_not_in_progress` | Moving a picked-up shipment to a route in preparation, or reassigning a whole route that is not in progress (FR-014, FR-015) |
| 422 | `past_service_date` | Creating a route for a past date (FR-002) |
| 409 | `route_in_progress` | Cancelling a route in progress (FR-017) |
| 422 | `courier_required` | Dispatching without a courier (FR-009) |
| 422 | `confirmation_required` | More than 15 shipments without `confirmed: true` (FR-005) |

## Endpoints

| Method and path | Request → Response |
| --- | --- |
| `GET /api/shipments/unassigned?date=YYYY-MM-DD` | → `{ shipments: UnassignedShipment[] }` with pickup point, rate zone, neighborhood, delivery window, COD amount, flags (FR-001) |
| `GET /api/routes/board?date=YYYY-MM-DD` | → `RoutesBoard` = `{ date, serverTime, routes: RouteSummary[], routesFromPreviousDays: RouteSummary[], unassignedCount }`; `RouteSummary` = number, courier, status, `completedStops`, `totalStops`, `codToCollect`, `atRiskCount`, `lateCount`, `pendingHandovers` (FR-018) |
| `POST /api/routes` | `{ id, actionId, serviceDate, shipmentIds, courierId?, confirmed? }` → `201 RouteDetail` (FR-002, FR-005) |
| `GET /api/routes/:id` | → `RouteDetail` = route + `stops: Stop[]` (each with `tasks`) + `events: RouteEvent[]` (FR-019) |
| `PATCH /api/routes/:id` | `{ actionId, version, courierId }` (route in preparation) → `RouteDetail` (FR-008) |
| `PUT /api/routes/:id/stop-order` | `{ actionId, version, stopIds: string[] }` → `RouteDetail`; `409 invalid_stop_order` (FR-006) |
| `POST /api/routes/:id/shipments` | `{ actionId, version, shipmentIds, confirmed? }` → `RouteDetail` (FR-011) |
| `POST /api/routes/:id/shipments/:shipmentId/remove` | `{ actionId, version }` → `RouteDetail` (FR-012) |
| `POST /api/routes/:id/dispatch` | `{ actionId, version }` → `RouteDetail`; `422 courier_required`, `409 courier_busy` (FR-009) |
| `POST /api/routes/:id/undo-dispatch` | `{ actionId, version, reason }` → `RouteDetail` (FR-026) |
| `POST /api/routes/:id/cancel` | `{ actionId, version, reason }` → `RouteDetail` (FR-017) |
| `POST /api/routes/:id/reassign` | `{ actionId, version, courierId, reason }` (route in progress) → `RouteDetail`; creates handovers for picked-up shipments; `409 courier_busy` (FR-015, FR-025) |
| `POST /api/shipments/:id/reassign` | `{ actionId, toRouteId, reason }` → `{ shipment, handover? }`; a handover is created only for a picked-up shipment moving to another courier, replacing any pending one (FR-014, FR-025) |
| `POST /api/handovers/:id/confirm` | `{ actionId }` → `Handover` with `resolvedOnBehalf: true` (dispatcher confirms for the courier; the courier's own confirmation is feature 003) |
| `POST /api/handovers/:id/cancel` | `{ actionId }` → `Handover`; the delivery task returns to the previous route (FR-025) |

Reasons are 5–200 characters. Removing uses `POST …/remove` because the API has no `DELETE`
endpoints.

## Changes to feature 001's contract

- **`actionId` on every mutation**: `PATCH /api/shipments/:id`, `POST …/void`,
  `POST …/confirm-fee`, and every master data `PATCH` also carry `actionId`, stored as the
  resulting event's `client_event_id`; a repeated one returns the current record.
- **`GET /api/shipments/board`**: each `BoardShipment` gains `routeId` and `routeNumber`.
- **`POST /api/shipments/:id/void`** and **`PATCH /api/shipments/:id`**: when the shipment is
  on a route, the same transaction removes it from the route or updates its stops (FR-013).
- **`PATCH /api/couriers/:id`** with `isActive: false`: the response includes
  `openRoutes: number` (FR-010).
