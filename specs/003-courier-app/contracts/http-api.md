# HTTP API Contract: Courier App

Extends the contracts of [feature 001](../../001-shipment-registration/contracts/http-api.md)
and [feature 002](../../002-routes-dispatch/contracts/http-api.md) and follows their
conventions: JSON under `/api`, Zod schemas from `packages/domain` (`schemas/courier.ts`),
session cookie, integer COP, Spanish error messages, no `DELETE` endpoints, `actionId` on
every mutation.

## Conventions added by this feature

- **Records** (FR-019): a courier record carries its own `id`, generated by the client; it
  is the idempotency key. Sending it again returns its stored outcome.
- **Time**: each record carries `occurredAt` (client clock) and the request carries
  `deviceNow`; the server stores `occurredAt` corrected by its offset to `deviceNow`.
- **Never refused for state** (FR-024): a well-formed record is always stored. The response
  says what happened to it: `applied`, `duplicate`, or `not_applied`.

| Status | `code` | When |
| --- | --- | --- |
| 409 | `no_exception_to_decide` | Deciding for a shipment that is not in "Novedad"; a return already decided accepts only a change to `new_attempt` (FR-029) |
| 409 | `not_held_by_courier` | "Recibido en oficina" for a package no courier holds (FR-041) |
| 409 | `record_not_revertible` | Reverting a record that is not the shipment's latest applied delivery, exception, or return (FR-035) |
| 409 | `office_not_configured` | "Recibido en oficina" before the office address is set (FR-041) |
| 413 | `photo_too_large` | Photo above 1 MB (FR-009) |
| 422 | `occurred_in_future` | A record on behalf with `occurredAt` later than now (FR-034) |

## Courier endpoints (role: courier)

| Method and path | Request → Response |
| --- | --- |
| `GET /api/courier/route` | → `CourierSnapshot` = `{ serverTime, sessionExpiresAt, route: CourierRoute \| null, handoversToGive: HandoverToGive[], heldOffRoute: HeldShipment[], notices: Notice[] }`. `CourierRoute` = number, service date, `stops` in order, each with kind, address, neighborhood, contact phone, and `tasks` (shipment id, tracking number, merchant, recipient name and phone, instructions, package count and size, delivery window, COD amount, status, flags, `blockedByHandover`, `problemNote`). Updates `couriers.last_synced_at` (FR-005, FR-022, FR-028) |
| `POST /api/courier/records` | `{ deviceNow, records: CourierRecordInput[] }` (1–50, in the order they happened) → `{ results: { id, outcome }[] }`. Each record is applied in its own transaction (FR-018–FR-026) |
| `PUT /api/courier/photos/:id` | Body: the JPEG image (`image/jpeg`, ≤ 1 MB) → `204`. `404` while its record has not arrived; repeating it is harmless (FR-023) |
| `POST /api/courier/notices/acknowledge` | `{ actionId, noticeIds, occurredAt }` → `204`; sets `acknowledged_at` only where empty (FR-027) |
| `GET /api/courier/summary?date=YYYY-MM-DD` | → `DaySummary` = counts of deliveries, exceptions, returns, pending stops; `cash`, `companyTransfer`, `merchantTransfer`, `disbursements`, `cashToHandOver` (FR-037) |
| `POST /api/courier/push-subscriptions` | `{ actionId, endpoint, keys: { p256dh, auth } }` → `204` (FR-040) |
| `POST /api/courier/push-subscriptions/remove` | `{ actionId, endpoint }` → `204` |

`CourierRecordInput` is a union by `kind`; every member has `id`, `shipmentId`, `occurredAt`,
and optional `location: { latitude, longitude, accuracyM }`:

| `kind` | Extra fields |
| --- | --- |
| `pickup` | — |
| `delivery` | `receivedByName`; `cashAmount`, `companyTransferAmount`, `merchantTransferAmount` (default 0); `note` (required when the total differs from the COD amount); `photos: { id, kind: 'proof' \| 'transfer_receipt' }[]` (at most 3 `proof`) |
| `exception` | `reason`; optional `note`; `photos` of kind `exception` |
| `problem` | `note` (5–200 characters) |
| `return` | `receivedByName`; `photos` of kind `proof` |
| `disbursement` | `amount` (> 0), `payee`, optional `note`; `photos` of kind `disbursement_receipt` |
| `handover_confirmation` | — |

## Dispatch panel endpoints (roles: owner, dispatcher)

| Method and path | Request → Response |
| --- | --- |
| `POST /api/shipments/:id/records` | A `CourierRecordInput` without `shipmentId`, plus optional `occurredAt` (default now). Stored with `on_behalf = true` for the courier who holds the shipment or whose route carries it → `{ id, outcome }` (FR-034) |
| `POST /api/shipments/:id/exception-decision` | `{ actionId, decision: 'new_attempt', serviceDate?, routeId? }` or `{ actionId, decision: 'return', routeId? }` → `Shipment`; with `routeId`, the stop is added under the rules of feature 002 (`409 route_not_in_progress`, handover when another courier's) (FR-029) |
| `POST /api/shipments/:id/office-receipt` | `{ actionId }` → `Shipment` with `heldAtOffice: true` (FR-041) |
| `POST /api/shipments/:id/clear-review` | `{ actionId, note }` → `Shipment` (FR-026) |
| `POST /api/courier-records/:id/correct` | `{ actionId, reason, receivedByName?, cashAmount?, companyTransferAmount?, merchantTransferAmount?, exceptionReason?, note?, amount?, payee? }` → `CourierRecord` (FR-035) |
| `POST /api/courier-records/:id/revert` | `{ actionId, reason }` → `Shipment` (FR-035) |
| `GET /api/photos/:id` | → the image. Owner and dispatcher: any photo; courier: photos of their own records. `404` when the object was deleted by retention (FR-036) |
| `GET /api/settings`, `PATCH /api/settings` | `{ actionId, officeAddress, officeNeighborhoodId }`; owner only for `PATCH` (FR-041) |

Reasons and notes are 5–200 characters.

## Changes to the contracts of features 001 and 002

- **`GET /api/shipments/:id`**: gains `records: CourierRecord[]` (with `outcome`, `onBehalf`,
  photos and their `uploaded` state, revert data), `attempts`, `heldAtOffice`,
  `custodyCourier`, `returnDecided`, `needsReview` (FR-036).
- **`GET /api/shipments/board`**: each shipment gains the flags `noPhoto`, `photoPending`,
  `collectionDiffers`, `pickupProblem`, `needsReview`; the board gains
  `exceptionsToDecide: number` (FR-033).
- **`GET /api/routes/board`**: each `RouteSummary` gains `courierLastSyncedAt` and
  `unacknowledgedNotices: number` (FR-033).
- **`GET /api/shipments/unassigned`**: also returns held shipments that are on no route, each
  with `heldBy: { courier } | 'office'` (FR-031).
- **`POST /api/routes/:id/shipments`** and **`POST /api/shipments/:id/reassign`**: accept held
  shipments; a shipment held by a courier gets only a delivery or return stop and requires a
  route in progress; one held by the office gets a pickup stop at the office first (FR-031,
  FR-041).
- **Every route and shipment mutation of feature 002** that affects a courier with a route in
  progress also creates a notice and sends a phone notification (FR-027, FR-040).

## Phone notification payload (FR-040)

`{ type: NoticeType, routeNumber?: number }`. No names, addresses, or phone numbers.
